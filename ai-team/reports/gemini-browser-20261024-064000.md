## 1. 結論（優先度順・最大3点）

1. **[高 / IME境界] 同一フレーム内で `Event::Ime` と `Key::Enter` / `Key::Escape` / `Key::Tab` が同時到着した場合、`TextEdit` より先にセル確定/キャンセルとして消費される (`crates/ui-egui/src/formula_bar.rs:221-245`, `359-367`, `500-505`)**
   - `editor_widget` 冒頭で `i.consume_key(..., Key::Enter)` 等を実行しているため、ブラウザ/IME（特に macOS Safari 等で変換確定の `compositionend` と `Enter` keydown が同一フレームにバッチされたケースや合成イベント）で、変換確定と同時に `app.commit_edit` が走りセル移動まで進んでしまうリスクがある。
2. **[中 / Web Host連携] `?host=parent` ブリッジの保存検知が `.xlsx` のみに限定されており、VBA保持ワークブック（`.xlsm`）保存時に `dirty` 状態が解除されない (`apps/gridcraft-web/src/host.rs:26`, `86-93`, `140-142`)**
   - `WORKBOOK_EXTS` が `&["xlsx"]` のみのため、`vba_project` を保持したブックを `.xlsm` として保存しても `is_workbook(name)` が `false` となり、`doc.saved = doc.wb.clone()` が更新されない。
3. **[中 / IME保護セル境界・Web API互換] シート保護下のロック済みセルでグリッド直接IME入力を開始すると、編集開始時には弾かれず確定時（`commit_edit`）に初めてエラーになり `app.editor` が残留する (`crates/ui-egui/src/grid.rs:2967-2985`, `crates/ui-egui/src/lib.rs:952-991`, `1048-1062`)。また Web クリップボード・保存・印刷にブラウザ API 制約の境界がある (`apps/gridcraft-web/src/web.rs:191-243`, `283-345`, `369-449`)**
   - 保護セル上で直接キー/IME入力すると `begin_edit` は成功してインラインエディタが開き、変換確定後の `Enter` でエラーダイアログが出た後も `app.editor` が閉じない。

## 3. 詳細根拠・再現手順・最小修正案

### 指摘1: 同一フレーム内の `Event::Ime` と `Key::Enter` / `Key::Escape` / `Key::Tab` の消費順序
- **根拠 (`path:line`)**:
  - `crates/ui-egui/src/formula_bar.rs:221-245`: `editor_widget` の先頭で `ui.input_mut` を呼び、`Key::Enter`（226-229行）、`Key::Tab`（230-232行）、`Key::Escape`（233行）を `consume_key` して `action` / `cancel` を設定している。
  - `crates/ui-egui/src/formula_bar.rs:359-367`: その後で `TextEdit::singleline(&mut ed.text)...show(ui)` を実行し、`Event::Ime(ImeEvent::Preedit / Commit / Disabled)` を処理している。
  - `crates/ui-egui/src/formula_bar.rs:500-505`: フレーム末尾で `if let Some((dr, dc, clear_Wait, refocus)) = action` により即座に `app.commit_edit(ctx)` と `app.move_active(dr, dc, false)` を実行している。
  - `crates/ui-egui/tests/ime_input.rs:47-61`: 現行の回帰テスト `enter_after_ime_commit_commits_cell_and_moves_selection_once` は、フレーム3で `[ImeEvent::Commit("日本"), ImeEvent::Disabled]`、フレーム4（別フレーム）で `[key(Key::Enter)]` を送っており、同一フレーム到着ケースをカバーしていない。
- **区分**: **コードで確認**（実機 Safari / Chrome でのイベント発火タイミング差は実ブラウザ未実施）
- **最小再現手順**:
  - `crates/ui-egui/tests/ime_input.rs` にて、プリエディット中に同一フレームで `[egui::Event::Ime(egui::ImeEvent::Commit("日本".into())), egui::Event::Ime(egui::ImeEvent::Disabled), key(egui::Key::Enter)]`（または `[egui::Event::Ime(egui::ImeEvent::Preedit("に".into())), key(egui::Key::Enter)]`）を投入すると、変換確定のための `Enter` でセル自体が確定し `active_cell` が `(1, 0)` へ移動する。
- **最小修正案と副作用**:
  - `crates/ui-egui/src/formula_bar.rs:222` の `ui.input_mut(|i| { ... })` 内で、`let has_ime = i.events.iter().any(|e| matches!(e, egui::Event::Ime(_)));` を判定し、`!has_ime` のときのみセル確定・移動・キャンセル用の `Key::Enter` / `Key::Tab` / `Key::Escape` を消費する（または `ed.ime_composing` が前フレームで `true` だったフレームの `Enter` / `Escape` をセル確定に使わない）。
  - **副作用**: 通常時の `Enter` 確定（IMEイベントを伴わないフレーム）には影響せず、同一フレームでIME確定と `Enter` が届いた場合の誤確定・二重移動のみを防げる。

### 指摘3: 保護セルでの直接IME入力開始時のガード欠落と、Web API（Clipboard / Save / Print）のブラウザ別制約
- **根拠 (`path:line`)**:
  - **保護セル + IME**: `crates/ui-egui/src/grid.rs:2967-2985` では `Event::Ime(Preedit/Commit)` や `Event::Text` を受けた際、`app.begin_edit(Some(String::new()), false)` を呼ぶ。`begin_edit`（`crates/ui-egui/src/lib.rs:952-991`）はシート保護（`sheet.protected && cell_locked`）をチェックしていないため、ロック済みセルでもインラインエディタが開いてIME入力が進み、`Enter` 確定時の `commit_edit`（`crates/ui-egui/src/lib.rs:1048`, `1058-1062`）で初めてエラーとなり、`self.editor` が `Some(...)` のまま残る。
  - **Web Clipboard (`apps/gridcraft-web/src/web.rs:191-243`)**: `services.copy` は `navigator.clipboard.write` / `writeText` を呼ぶが、`services.paste_text` / `services.paste_html` は未設定（`None`）。そのためリボン/メニューの「貼り付け」ボタン（`crates/ui-egui/src/lib.rs:487-491`）はアプリ内クリップボードのみを参照し、OSクリップボードからの貼り付けは `Cmd/Ctrl+V` による `egui::Event::Paste`（`crates/ui-egui/src/grid.rs:2964`、プレーンテキストのみ）経由となる。
  - **Web Save (`apps/gridcraft-web/src/web.rs:369-449`, `473-494`)**: `showSaveFilePicker`（File System Access API）は Chromium 系（Chrome / Edge）専用であり、Safari / Firefox では `Reflect::get(&win, &"showSaveFilePicker")` が `undefined` となって `trigger_anchor_download`（`<a download>`）へフォールバックする。また `save_file` は非同期 Promise の先頭で呼ばれるが、Safari で非同期処理後に `<a download>` をクリックするとユーザージェスチャ期限切れ扱いになる可能性があるため、フォールバック分岐は `await` 前に到達する現在の構造（`showSaveFilePicker` が無ければ `await` せずに `trigger_anchor_download` へ進む `web.rs:371-376`, `449`）を維持する必要がある。
  - **Web Print (`apps/gridcraft-web/src/web.rs:283-345`)**: `display: none` の `iframe` に PDF Blob URL を設定して `content_window.print()` を呼ぶ実装。Safari では非表示（`display: none`）の PDF `iframe` に対する `print()` が空ページまたは無反応になるケースがあるため、実機 Safari で動作しない場合は `width: 0; height: 0; position: fixed; visibility: hidden` への変更が必要になる。
- **区分**: 保護セルとAPI配線は **コードで確認**、Safari / Firefox での実挙動は **実ブラウザ未実施**。
