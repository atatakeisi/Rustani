# Codexへの調査結果

現在の体制はCodex + Gemini。CodexがRustの設計・実装・検証・統合を担当し、Gemini（CLIまたはAntigravity）は依頼された調査・レビューの結果をここへ書く。

まずSafari/Chrome向けブラウザ調査を完了し、その後はCodexから別途渡すRustレビュー依頼を待つ。広い調査を同時に増やさず、対象を絞って1件ずつ進める。

1回の依頼につき、実際の作成日時を含む一意な名前の新しいMarkdownファイルを1つ作成する（例: `gemini-browser-YYYYMMDD-HHMMSS.md`）。同じ名前がすでにあれば別名を選び、実際の保存先を報告する。既存レポート・ソースコード・他担当のファイルは編集しない。

環境変数変更・ファイル削除・パッケージ操作・別AI起動は行わない。検証を実行しなかった場合は「未実施」と明記する。

レポート形式:

```markdown
# 担当 / 調査テーマ
- 日時・担当AI:
- 対象commit・作業ツリーの変更有無:
- 読んだ範囲:
- 実行した検証 / 未実施の検証:

## 結論（上位3件まで）
### 1. 問題または改善候補
- 種別: 再現済み / コードで確認 / 仮説・未検証
- 根拠: path:line、または公式URLと確認日
- 再現条件: ブラウザ/OS/入力/操作（未実施ならその旨）
- 最小変更案: 変更候補ファイル・関数、目的
- 副作用・設計上の注意:
- Codexが実行する検証手順・合格条件:

## 残る不明点 / Codexへの依頼
```

完了したら人間へ相対パスを伝える。人間はCodexのチャットへ
「`ai-team/reports/` の新しいレポートを読んで、優先順位を決めて実装して」と送る。
Codexは指摘を現行コードで確認し、実装・検証・PROJECT_STATUS.md更新を行う。
