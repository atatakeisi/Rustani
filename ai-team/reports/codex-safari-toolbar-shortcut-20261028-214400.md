# Safariツールバー操作による誤テーブル作成の修正

日付: 2026-10-28 JST / 基点: `ea9addf6`

## 問題と前回検証の不足

Safari Web Appで⌥⌘Tを押すとツールバーを表示できるが、Rustaniも⌘Tとして処理し、アクティブセルにテーブルと自動見出しColumn1を作成していた。`keymap::dispatch` はOption付きであることを区別していたが、未処理イベントを受けた `ribbon::shortcut` が修飾キーを検査せず実行していた。

前回の10複合QAはコピー/貼り付け/ズーム、再計算、保護/入力規則、マクロ、保存往復、指定ダイアログ等のテストだった。Safariのツールバー切替キーをブラウザとアプリが同時に受け取る経路は未検証だった。画像に写ったオートフィルターのポップアップも前回の翻訳確認対象から漏れていた。

## 修正

- 共通ショートカット処理で、追加Option/Altや未定義のShift組み合わせを通常のCommand/Ctrlの編集操作に読み替えない。拡張ショートカットは既存の専用ディスパッチで処理する。
- macOSのCommand付きキーに付随するTextイベントが、イベント順序によってセル編集を開始しないよう抑制する。Windows AltGrによる文字入力は維持する。
- フィルターポップアップの昇順/降順・検索・全選択・検索結果の全選択・空白セル・適用を日本語化。生のセル値と内部の空白マーカーは保持する。
- スナップショットツールに `--filter-menu` を追加し、Alt+Downによるメニューの実描画を確認できるようにした。

## 回帰テスト

`browser_shortcut_isolation.rs`（4テスト）:

1. macOS ⌥⌘Tのキーのみ、キー→Text、Text→キーの異なる3経路で、ブック・選択・履歴・セル編集・テーブル数に変化がないこと。
2. Option+Command/Alt+Ctrlの18キーについて、テーブル作成、書式、保存、新規、閉じる、検索等へ誤分岐しないこと。
3. 定義されていないCtrl+Shiftの14キーが、通常の書式やFillに誤分岐しないこと。
4. 通常のCmd/Ctrl+Tによるテーブル作成、Undo、太字、Windows AltGr文字入力の正常系。

`filter_menu_enter.rs`（追加2テスト）:

- 日本語の各コントロール表示、英語のユーザー値「Apply」の保持、空白セルの除外適用。
- 日本語「空白」による絞り込みとEnter適用で、セル値や選択を変えずに空白行のみ表示すること。
